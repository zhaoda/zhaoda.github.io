今天（11 月 3 日）起，你用 Claude 写出的东西，可能已经带上了一道看不见的印记；11 月 7 日，Grok API 也要默认跟进。AI 生成文本正在进入"全面带印"的时代，但印在谁手里能验、验出来算什么，远没有看上去那么简单。

<!--more-->

## 一周之内，两家大厂先后落子

先把时间线摆清楚。

Anthropic 从 11 月 3 日起，把隐形文本水印扩展到四款模型：Mythos 5、Opus 4.7、Opus 4.6 和 Sonnet 4.6，走 Amazon Bedrock 的要多等几天。Opus 5.5 这类新模型早就带印了，8 月 2 日之前发布的更老模型会在未来几个月内陆续跟上。图片类输出不走这套，改用签名的 C2PA 来源元数据。

xAI（文档中现称 SpaceXSI）则把日子定在 11 月 7 日：从那天起，Grok API 默认给文本输出加隐形水印，覆盖 grok-4.7、grok-4.6、grok-4.5、grok-4.3 以及 grok-4.20 的 reasoning、non-reasoning、multi-agent 三个变体。范围不只普通回答，还包括结构化输出和工具调用参数，两个主流 API 全覆盖，全球端点和区域端点都算在内。开发者不用改请求，响应格式也不变，只多了一个 `x-watermark` 响应头：值为 `true` 就表示这次输出带印。

两家给出的理由是同一个：欧盟《人工智能法案》第 50 条的透明度要求，2026 年 8 月 2 日起生效，要求生成式 AI 输出带机器可读标记。Anthropic 还明说，因为目前做不到按地区切分，所以这次是全球同步上线。

## 这印到底是什么：不在字面上，在选词里

先说清楚最容易误解的一点：这种水印不是在文本里藏字符、加符号。它是在模型生成时，用一把秘密密钥轻微引导选词，让词的选择带上统计规律，读者肉眼什么都看不出来。

Anthropic 用的方法是 Google DeepMind 在 2024 年发表的 SynthID-Text 的一个变体，按它的说法不增加字符和 token，不改变可读性和质量，也不额外收费；xAI 的说法类似，不改变响应质量和生成速度。

验印的方式也类似：只有持有密钥的一方能检测。Anthropic 的检测 API 还在非公开预览阶段，只对监管机构、媒体、事实核查机构和研究者这类组织开放，普通用户用不了。xAI 的检测同样要申请才给，结果是统计性的：带印、没带印，或者不确定，文本越长信号越强。

也就是说，从今天起，AI 文本的"出身证明"存在，但钥匙不在你手里。这就是我要说的第一件事。

## 第一件事：检测权不对称，普通人验不了

水印扩围听起来像透明度进步，但现阶段的透明是单向的：厂商能验，你不能验。

这对程序员的直接影响在评审和内容管线里。如果你接手一段 Agent 生成的代码注释、技术文档、PR 描述，想确认它是不是 AI 写的，你手头没有公开检测器。Anthropic 的 Claude Content Checker 只能查文件（图片、文档）的来源凭证，查不了纯文本水印。指望"肉眼识别水印"更是无稽之谈——它本来就设计成看不见。

我的判断是：别把水印当成你能用的反作弊工具。它现阶段更像厂商和监管之间的合规通道。团队里对"是不是 AI 写的"的认定，还是得回到评审、测试和责任制本身。

## 第二件事：水印有个采样参数缺口，合规别只押在它身上

先说明口径：扩围消息来自 Anthropic 10 月 27 日发给平台客户的邮件，邮件文本是在 X 上流传的，并非 Anthropic 公开发布的公告。下面这条要按"据报道"来理解。

据报道，对 Opus 4.6 和 Sonnet 4.6，水印只在 temperature、top_p、top_k 保持默认值时才生效，改了其中任何一个，输出就可能不带印，而调用方未必知道。

这对做 Agent 工程的人是个实打实的坑：我们调 Agent 时改 temperature 是家常便饭。如果你的合规方案写的是"输出自带水印"，只要管线里有人动过采样参数，这个假设就悄悄失效了。至于 Mythos 5 和 Opus 4.7 是否有同样问题，目前没有明确说法。

所以实战结论很直接：如果你在欧盟市场有标记义务，不要把水印当成唯一防线。一是把采样参数默认值写进管线配置的显式约定，改动留痕；二是对 Grok 这类给了 `x-watermark` 响应头的接口，把这个头和请求一起记进日志——这是你目前唯一能逐条拿到手的带印证据。

xAI 那边的开关也值得注意：关水印是团队管理员按模型逐个关的，团队内所有 API Key 一起生效，5 分钟内对新请求生效，关之前还要确认有法律例外适用。关不关是团队级决策，别让某个成员在控制台上随手点了。

## 第三件事：验出印来，也只证明"Claude 参与过"

Anthropic 自己把话说得很清楚：水印只能说明 Claude 在某个环节参与过，不能区分它是全文写了、改了，还是只翻译了一遍；全文改写会把印洗掉，没有印也不能据此断定是人写的。

这句话直接决定了水印在纠纷里的分量：它不能单独支撑纪律处分、违约认定或者"这是 AI 抄袭"的指控，检测结果本身也只是概率，不是铁证。

我把这个理解成一条工程原则：水印是"出身线索"，不是"责任判决"。你用 Claude 润色过的文档被验出印，不等于"全文都是 AI 写的"；一段没印的文本，也不能据此断定是人写的。

## 对 Agent 工作流，我的四条实操建议

落到日常工作，我会这样调整：

1. **管线里记下水印状态。** 用 Grok API 的，日志里同时存 `x-watermark` 头；用 Claude 的，把模型版本和采样参数写进运行记录。将来真要追溯，至少有据可查。
2. **别动默认采样参数还指望水印兜底。** 动了参数，就当水印可能不在，自己补一道显式标记。
3. **评审标准不变。** 代码该跑测试跑测试，文档该核实核实。水印验不出来，也不改变"谁提交谁负责"。
4. **别用"洗印"工具自欺欺人。** 改写能去掉水印这件事，恰恰说明水印防不住有心人；把它当合规护身符，或者当反 AI 检测的军备竞赛，都是走偏。

## 结语：印是印，信任是信任

11 月 3 日和 11 月 7 日这两个日子，标志着 AI 文本水印从"新模型试点"走到了"全量默认"。这是监管驱动的大势，欧盟第 50 条只是第一块多米诺骨牌。

但我的态度是谨慎乐观：水印让 AI 文本"可追溯"第一次有了工程抓手，这是好事；可检测权在厂商手里、采样参数能悄悄关掉它、检测结果只是概率——这三点决定了，它现在还撑不起"透明"这个词的全部重量。

程序员能做的，是先把自己的管线摆正：记下该记的头，管住该管的参数，别把概率当判决。至于水印会不会变成像 HTTPS 那样人人可验的基础设施，就看检测 API 什么时候真正开放了。我会继续盯着。
