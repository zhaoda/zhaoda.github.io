昨天（10 月 26 日）OpenAI 发布了 GPT-6.1 Terra，同一天它也以正式版（GA）进了 GitHub Copilot。发布稿里最抓眼球的一句话不是跑分，而是定价：标准 API 价格比 GPT-5.6 Terra 和 GPT-6.1 Sol 低 50%。我先说结论：这不是一个让你换掉主力模型的发布，而是一个让你重新算账的发布——当「动手干活」便宜了一半，很多以前不值得交给 Agent 的杂活，突然值得了。

<!--more-->

## 先把事实摆清楚

按 OpenAI 10 月 26 日的发布和当天的报道，GPT-6.1 Terra 的定位是这样几条：

- **价格**：API 标准价格比 GPT-5.6 Terra 和 GPT-6.1 Sol 低 50%。多家报道给出的 API 价目是每百万输入 token 约 1 美元、输出约 5 美元，也就是 Sol 的一半。
- **能力方向**：通信和电脑操作任务——起草提案、读技术图纸、填表、剪视频，以及最典型的一例：把发票读出来、录进财务软件。说白了，它瞄准的是量大、重复、步骤清楚的工作，而不是最难的那道推理题。
- **入口**：同一天起，ChatGPT Work 和 Codex 的 Plus、Pro、企业版和教育版用户可用，开发者走 API；GitHub Copilot 也在同一天宣布 GA，覆盖 Pro、Pro+、Max、商业版和企业版，模型选择器里就能选，覆盖 VS Code、Visual Studio、Copilot CLI、云端 Agent、网页端、移动端和 JetBrains 等 IDE。
- **Copilot 里的定位**：GitHub 的原话是「为日常 Agent 编程和终端工作设计，成本低于 GPT-6.1 Sol」，早期测试里它比 GPT-5.6 Terra 解决了明显更多的终端和 C# 任务，且「在范围明确的任务上以专注、收敛的步骤工作」。

注意两个限定词。第一，Copilot 的上线是**逐步推送**，你今天在选择器里看不到它，不代表没资格，只是还没轮到你。第二，Copilot 里它是**按供应商目录价单独按用量计费**，不是「进了套餐就随便用」——企业版和商业版管理员还可以通过模型策略关掉它，默认新模型是自动开启的，除非管理员关了全局默认或单独关了 Terra。

## 真正值得讨论的不是跑分，是「每任务成本」

OpenAI 公布的 Agent 基准对比里有个很值得玩味的数字：Terra 在 Agents' Last Exam 上得分 60.0%，Claude Opus 5.5 是 63.2%，但 Terra 每任务成本约 1.01 美元，Opus 约 8.82 美元。先泼一盆冷水：这是厂商自己公布的对比，对手还是上一代模型，绝不是独立评测，不能直接当成选型结论。

但这个数字的方向是对的，而且它点出了 Agent 时代一个被低估的指标：**不是模型一次答对的概率，而是完成一个任务要花多少钱、烧多少 token、返工几次**。以前 Agent 贵的时候，我们的本能是「把任务攒大了一次性交给最强的模型」；现在动手成本腰斩，合理的拆法反过来了：把大任务拆成一串范围明确的小任务，让便宜模型一个一个啃，难啃的骨头再升级给强模型。

我自己的判断是，Terra 这类模型的正确用法不是「替代 Sol」，而是「扩大 Agent 的工作半径」。以前你不会让 Agent 去做的事——批量整理发票、按模板填几十张表、跑一遍终端里那些步骤固定但手敲烦人的命令——现在可以先让它试，试错成本低了，人的复核成本反而成了新的瓶颈。这和我之前写过的结论是一脉相承的：Agent 提效的上限往往不在模型，而在评审和复核那一环。

## 给程序员的三条实战建议

**第一，先拿三类任务试水，别一上来就换默认模型。** 一是终端里步骤固定的活：环境检查、批量改名、日志里按规则捞信息；二是范围明确的 C# 或日常代码小任务，GitHub 早期测试的强项恰好在这里；三是文档和表单类杂活：按模板起草、把结构化信息从一种格式搬到另一种格式。这三类都有一个共同点：结果好不好一眼能看出来，复核成本低。

**第二，用「自己的任务」跑分，而不是抄发布稿的跑分。** 做法很直接：固定 5 到 10 个你团队真实会遇到的任务，同一份提示词分别跑 Terra 和你现在的默认模型，记三项：一次通过率、返工次数、总 token 花费和复核花了你几分钟。如果 Terra 在其中六七成任务上一次通过且复核不超过两分钟，它就值得成为这类任务的默认选项；否则，省下的 token 钱会被你的复核时间吃回去。

**第三，企业用户先查模型策略，再谈推广。** Copilot 商业版和企业版的管理员可以在模型策略里控制 Terra 的开关，默认是自动开启的。如果你是管理员，先确认两件事：Terra 是否在你们的允许列表里，以及用量计费走的是谁的账；如果你是普通开发者，发现选不到它，先问管理员、再等逐步推送，别绕过策略自己接 API——省下的钱不值得搭上合规风险。另有一个时间点值得记在日历上：有报道称 Copilot 里 GPT-5.6 Terra 计划于 11 月 16 日退役，还在用老 Terra 的团队，这次换代正好一并处理。

## 别被「半价」带偏的三个坑

**坑一：把「便宜一半」理解成「能力只差一半」。** 价格和能力从来不是线性关系。Terra 便宜，恰恰是因为它被定位在「够用就好」那一档：范围明确的任务它很利索，开放式、需要长链推理和跨系统判断的任务，它未必比 Sol 稳。选型时先问「这个任务的难度天花板在哪」，再问「多少钱」，顺序别反了。

**坑二：把电脑操作等同于「可以撒手不管」。** Terra 主打的电脑操作——读屏、点击、填表——恰恰是风险最容易藏起来的地方：它填错一个数字、点错一个按钮，比答错一道题更难发现。凡是涉及付款、签名、删除、对外发送的操作，审批必须留在人手里，这一点 Anthropic 在 Duet、OpenAI 在 Dots 上的做法都一样：敏感动作先停下来问人。便宜不能成为放手不管的理由。

**坑三：只算 token 价，不算总账。** 一次任务的总成本 = token 费 + 返工 token + 你的复核时间 + 出错后的修复成本。Terra 的 token 费是降下来了，但如果它在你的任务上返工率明显更高，总账可能反而更贵。这也是为什么我建议先小范围对照跑，而不是全量切换——Agent 的账，要按任务算，不能按模型标价算。

## 结论

GPT-6.1 Terra 的发布，标志着大厂竞争的下一个战场从「谁更聪明」转向了「谁在够用的智能上更便宜」。对开发者来说，这不是换模型的问题，而是换拆法的问题：把任务拆小、把便宜模型放在前面、把复核和审批留在人手里，Agent 能接的活会比以前多得多——前提是你先在自己的任务上验证，而不是在发布稿里验证。
